## 1. The patch

`run guarded` now refuses unless the executable launcher in argv resolves — by
`realpath` — to the same file as `--script`.

D-11 already proved the file *named* by `--script` is the pinned construction member. It
never asked whether argv actually **runs** that file, so a run could be authorized and
integrity-checked against one launcher and execute another; the receipt's script hash,
import closure and attestation would all describe a program that never ran.

`runs.validate_script_argv_identity()` locates the launcher **positionally**, never by
guessing which token is an interpreter:

* **argv[0] is the executed program.** If it resolves to `--script`, that is a direct
  execution and the invariant holds outright.
* **Otherwise argv[0] is an interpreter,** and `--script` must be the **first file-bearing
  operand** it is handed. Any earlier file would be the thing that actually executes, so it
  denies — which is what stops the pinned script from being parked harmlessly later in argv.

Wired in `wrapper.guarded_run` **after** `validate_bound_construction` and **before**
`runs.begin`, so a DENY opens no record. That order is deliberate and has its own regression
test: the new gate must not shadow D-11's coverage of an unbound construction. The outcome is
bound into the receipt as `attestation_block.script_argv_binding`, so the check leaves a
trace rather than passing silently.

**No pseudo-authenticated env-var / run-id / token scheme was added**, per the owner ruling.
D-11's per-member re-hash is untouched and still runs first.

**Applies in both modes.** D-11 is production-only because it is about construction
integrity; this is about whether the run record describes reality, and a diagnostic receipt
naming the wrong program is just as false.

## 7. Scope — stated so it is not overread

* **PATH is not searched**, by design: a bare `bash`/`python3` resolves to nothing and is
  never mistaken for the launcher. A PATH-planted interpreter is therefore not detected —
  an OS-level bypass, out of scope by the same ruling that authorized this patch.
* The store runs in **witness-advisory mode** (`authority.py:318-357`). No external witness is
  installed, so `brittlectl anchor verify` reports `MISSING` while the authority chokepoint
  surfaces it as **advisory** and does not refuse. That is documented Guard v1 scope — *not* a
  drift between two surfaces — and it bounds what "guarded" claims here.
