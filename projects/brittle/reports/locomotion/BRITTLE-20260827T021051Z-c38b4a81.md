## 6 · Root cause, owner, fix, confidence

### Class 2 — `rpred_bad` / `pcad_zero_on_dying_step_bad`

**Root cause (what makes the gate fail): PROBE.** The dying-step mask uses the post-truncate `out["done"]`, a strict superset of the trainer's `dm`.
**Owning file/function:** `rl/integrity/probe_reward_chain.py` — `RewardChainRecorder.on_final`, lines **180-181** (R-PRED) and **227-229** (dying-step scoping).
**Causal evidence:** §3 — mask-only variation, 167 → 0 bit-exact; §2 — 0.0 on 1515 true terminations.
**Minimal fix:** mask with the trainer's population, not the final `done`. The probe **already captures `truncated`** (`:275`, and it is in `stream_hashes`), so no new capture is needed.
**Confidence: HIGH.**

⚠ **Do not implement it as `done & ~truncated`.** I checked and that identity is false in general: `out["truncated"]` is not written only at `:3573` — it originates in the sim (`train_tip_gpu.py:436` ← `batch_sim_tip.py:1480`, kernel `batch_sim_tip.py:748` sets `trunc[w] = episode_step >= max_steps`), and the sim's own `done` already folds truncation in (`kernels_tip.py:627`). A sim-timelimit row therefore has `done=1, truncated=1` **and is in `dm`**, so `done & ~truncated` would silently under-mask it — the probe would then stop flagging rows the trainer really did zero. **The correct fix is for the probe to capture the trainer's `dm` directly** (record it in the existing wrapper at the point the trainer applies it), or equivalently `done & ~fin` with `fin` reconstructed as `(phase >= n-2) & ~sim_done`.

**This evidence is measurably uncontaminated by that case**, so the §3 result stands unaffected. The card runs `--max-steps 660` while the probe captures 256 steps, making `episode_step >= 660` unreachable — and the streams confirm it rather than merely implying it:

| population | n | `fell=1` | `stalled=1` |
|---|---|---|---|
| terminations (`done & ~truncated`) | 1515 | **1515** | 0 |
| truncations (`done & truncated`) | 584 | **0** | **0** |
| total | **2099** = `n_done` exactly | | |

Zero rows satisfy `truncated & (fell | stalled)`, so every truncated row here is a trainer-side `fin` row. On a capture longer than `max_steps` this partition would no longer hold, which is exactly why the fix must not be written against `truncated`.

**Co-located TRAINER defect (real, currently unjudged): truncation respawn skips the episode-start reset.**
**Owning file/function:** `rl/mjw/train_tip_reftrack.py` — reset block `:3384-3396` runs against pre-`fin` `dm`; truncate respawn `:3568-3596`; `dm` refreshed only at `:3600`.
**Causal evidence:** §4 — 0.0 % staleness after terminations vs 76.0 % after truncations, persisting to 79.3 % at +10 steps.
**Minimal fix:** apply the same clears to `fin` rows — either move the truncate block above `:3384`, or re-run `:3384-3396` for `fidx` after the teleport. Smallest scoped change: at `:3596`, add the `fin` rows to the existing clear set.
**Confidence: HIGH.**

### Class 1 — `rcomp_parent_maxdev`

**Root cause: TRAINER transient**, same ordering defect, surfacing through an uncapped hold-still tax; **secondarily**, an absolute tolerance that a rare high-magnitude row can breach.
**Owning file/function:** `rl/mjw/train_tip_reftrack.py` — `foot_trans` `:2988-2989` (uncapped when `hold_tax_cap == 0`), fed by `prev_foot_xy` refreshed at `:3384` before the `:3574` teleport.
**Causal evidence:** §5 — 7 outliers, 5 after truncations (13× enriched), `r_lift` delta ≈ −4700 on exactly those steps, maxdev exactly one ULP at `|parent|`max, and 7.63e-06 (passing) once the outliers are excluded.
**Minimal fix:** fixing the §4 reset ordering removes the teleport-displacement read, which should remove the transient. Independently, `foot_trans` should be capped or zeroed for rows respawned this step — an uncapped ×20 velocity term corrupts PPO advantages whether or not the gate notices.
**Do NOT rescale `PARENT_FOLD_TOL` as the fix** — that would hide a real transient. If a tolerance change is wanted afterwards, make it relative (a small multiple of `ULP(max|parent|)`), not absolute.
**Confidence: HIGH on the attribution and the ULP arithmetic; MEDIUM on "rounding only", because the per-world term streams needed to exclude a semantic error confined to those 7 rows are not captured.**
