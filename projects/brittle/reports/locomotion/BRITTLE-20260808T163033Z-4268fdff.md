## 3. ★★★★ THE STOP: Guard exposes no authenticated execution-context marker

The ticket said: *inspect whether Guard exposes an authenticated execution-context marker to the
child; if no reliable marker exists, STOP and report the control-plane gap; do not invent another
decisions.jsonl parser or pseudo-Guard check.* **It does not exist.**

```
brittlectl.py:219   W.guarded_run(state_dir, basis, unit, mode, argv, script, repo_root,
                                  campaign_ref, out_dir, input_subjects=…, ts_start=…,
                                  capture_dir=…)            <- NO env= argument
wrapper.py:114      def guarded_run(…, env=None, …)
wrapper.py:190-191  subprocess.run(argv, capture_output=True, cwd=repo_root,
                                   env=env if env is not None else os.environ.copy())
```

The child receives an **unmodified copy of the parent environment**. No run id, no decision id, no
nonce, nothing. **A launcher cannot verify it was invoked by the Guard**, so "Guard is the single
PPO execution path" cannot be *enforced from inside the launcher* today — only *practised*.

**What I did instead of inventing a check:** I **removed** the launcher's `decisions.jsonl` parser
entirely. It was a second, weaker authorization engine — it checked four fields and, as Red found
(C-1), *not* the decision's unit, so it would have accepted a C11S15-scoped grant the Guard
refuses. Two entry points, two answers. What remains is a plain acknowledgement, and the launcher
says so in its own refusal text: *"This is an anti-accident acknowledgement, NOT authorization."*

**Direct launch refuses** — `TC_MODE=run bash launch_acquisition.sh` → **exit 2**, pointing at the
sanctioned `run guarded` command.

**The minimal control-plane change that would close the gap** (a control-plane edit, out of scope
here and needing its own authorization): have `brittlectl` pass `env=` to `guarded_run` carrying
the freshly-minted `run_id`, and let a launcher require it. Until that exists, the real defences
are that `run guarded` is the only sanctioned entry point and that the D-11 bound-construction gate
re-hashes the launcher before executing it.

**`--script` / argv decoupling (Red C-1):** proven identical for the prepared command — same
realpath, same bytes `4f354fc205ca93aa`, equal to the `launcher-c11s15tc-acquisition` pin.
`runs.py:293-315` only sets `script_bound` when a member's realpath equals `realpath(--script)`; it
never compares argv to `--script`, so the identity is asserted here explicitly rather than assumed.
