# 12U-C11S15CY — Direct Same-Foot Cadence Signal: **`DIRECT CADENCE SIGNAL LICENSED — weight=17.5`**

## The signal

```
T_cmd = 1 / c_cmd                                        [s, same-foot period]
for each foot f ∈ {R,L}, each COMPLETE touchdown→touchdown interval i:
    e_{f,i} = (T_meas_{f,i} − T_cmd) / T_cmd             [dimensionless]
    ρ_{f,i} = min( huber_0.25(e_{f,i}) , 0.4688 )
p_cadence = −( mean_i ρ_{R,i} + mean_i ρ_{L,i} ) / 2
```

Four choices, each answering a specific way the previous term failed:

* **Normalised** by `T_cmd` — so the minimum sits at *each world's own* command. This is the one
  property `p_tempo` lacked.
* **R and L averaged separately, then combined** — turning lengthens one foot's stance; averaging
  the per-foot means cancels it, so curvature is not taxed as a tempo error.
* **Bounded** (hard cap 0.4688 = Huber at |e| = 2) — `p_tempo` was rejected partly on magnitude;
  no single pathological world can dominate a batch.
* **Same-foot by construction** — touchdown-to-touchdown of *one* foot, so no step-rate/cadence
  convention can be misread. Edges come from the pinned estimator's own `path_speed_v1._rising`,
  not a second implementation.

**1. Penalises the inverted seed most at low commanded cadence.** |p| = **0.1267 / 0.0851 /
0.0027** at c = 0.70 / 0.85 / 1.00. Strictly ordered.

**2. Approaches zero as measured → command.** The closest cell (c = 1.00, e = −0.085) costs
0.0041 against 0.1260 at the worst — a **31×** spread.

A foot with no touchdown for > 3·`T_cmd` is charged the cap for that window, so *not walking* is
the most expensive option rather than the cheapest.

## Weight — derived, not inherited

Ledger: `track_feet` +2.2411, `track_jnt` +3.2441, `track` +8.1223, **total positive +23.9706**,
`fall_cost` −50.0.

Calibration rule, stated before the number: **the worst cell must cost no more than one mid-size
shaping term** — `track_feet`. Worst observed raw |p| = 0.1294 →
**w = 2.2411 / 0.1294 = 17.31 → w = 17.5**.

| cell | raw | w·raw | % of positive reward | % of fall cost |
|---|---|---|---|---|
| CY straight c=0.70 (worst) | 0.1260 | **2.205** | **9.2 %** | 4.4 % |
| CY straight c=0.85 | 0.0837 | 1.465 | 6.1 % | 2.9 % |
| CY straight c=1.00 | 0.0041 | 0.073 | 0.3 % | 0.1 % |
| any reference (floor) | 0.0023 | 0.041 | 0.17 % | 0.08 % |

For contrast, `p_tempo` at its **smallest** candidate weight cost **2.4×–9.0× the entire positive
reward**. This term's worst cell costs **9.2 % of it** — meaningful, and subordinate to the
walking basin.

⚠ The number 17.5 looks large only because the raw penalty is small, bounded and normalised. **A
weight is meaningless without its raw scale** — that is exactly what made the inherited
`ss_tempo_w = 3.0` dangerous, and why this one is derived from the measured ledger.

## Minimum trainer change

Additive, default-off, and it touches no existing term:

1. **Per-world `T_cmd_w = 1/cadence_cmd_w`.** Already computed — the trainer builds `_sp_w =
   1/cadence_cmd` at `:4580` for `set_rp_step_period_w`. Reuse it; do not recompute.
2. **Per-world, per-foot last-touchdown step index** (2 × `nworld` int32) and a rising-edge test
   on the existing `loaded` array — the same array `p_tempo` already consumes at `:2496`.
3. **On each same-foot touchdown:** `reward += −w · min(huber_0.25(e), 0.4688)`; plus the stall
   check charging the cap when a foot exceeds 3·`T_cmd` without landing.
4. **One flag `--cadence-track-w`, default `0.0`**, so the default build stays bit-identical to
   today and the term is opt-in.

No change to `p_tempo` (leave it at 0.0), no reference change, no observation change, no change to
the command interface.
