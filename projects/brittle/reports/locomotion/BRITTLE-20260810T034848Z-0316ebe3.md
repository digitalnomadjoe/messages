## 1. The schedule, built from data before any training

The reference family is a **grid** — strides {0.118, 0.153, 0.180, 0.219, 0.240} × cadences
{0.70, 0.85, 1.00} — not a curve. A schedule therefore means *choosing* a curve through it.

**`c(v) = clip(2.1475·v + 0.4846, 0.70, 1.00)`** — one linear law, no kinks, spanning exactly the
family's cadence range over exactly its speed range.

| vx | c_sched | stride | inside validated envelope |
|---|---|---|---|
| 0.1003 | 0.7000 | 0.1433 | yes |
| 0.1530 | 0.8132 | 0.1882 | yes |
| 0.2040 | 0.9227 | 0.2211 | yes |
| 0.2400 | 1.0000 | 0.2400 | yes |

Stride is **monotone increasing 0.1433 → 0.2400 (+67 %)** against cadence's +43 %, so stride does
more of the work — polish priority 1 by construction. Deliberately **not** fitted to realized
cadence, which is inverted (row 137); fitting it would have baked the inversion in.

**No new objective.** The existing `cadence_track_w = 19.5` now tracks the schedule. With
`c = f(v)` the strata relation `stride = v/c` collapses to a single curve, so the cadence and
speed objectives **cannot disagree** — the conflict row 137 measured.

I measured these rather than optimizing any of them, per the ticket. **Priorities 2, 4 and 5 need

curvature and survival, not pelvis pitch or per-member touchdown quality. I would build that
before a polish run, so the polish has something to be judged against.

## 4. ⚠ A heading-drift observation I am flagging as a hypothesis, not a finding

The un-scheduled long run (row 137) went `NETYAW` 5.7° → **47°** between 1.5M and 3M steps, with
governor load 0.12 → 0.52. This pivot run ends at **4.1°** and **0.04** after 884,736 steps.

Plausible mechanism: with `c` and `v` independently commanded, `stride = v/c` let the policy meet
a speed command at almost any cadence, and it drifted into gaits satisfying both commands while
wandering in heading. Tying `c = f(v)` removes that freedom.

**But the two runs differ in step count as well as in the schedule**, so this is not a clean
single-variable comparison and I am not claiming it as a result. A matched-budget comparison would
settle it.

## 5. Recommendation

**The pivot is working and should continue.** Speed authority is the best this lane has produced
and stability is untouched. The next unit should be gait polish aimed squarely at **priority 1**,
because stride geometry is now the single quantified gap — and note it may be partly a *command*
problem rather than a capability one: the pre-pivot policy already produced a 0.245 m stride at
`vx=0.240`, so the long stride exists in the policy and is simply not deployed across the range.

**Before that, build the missing instruments** for priorities 2, 4 and 5. Gating a polish run on
quantities the evaluator cannot report would repeat the span mistake from row 135.

done.** Actor 296,972 params, checkpoint 1,544,224 B, workstation-CPU p99 0.072 ms — a proxy only.
