## 3. ⚠ Four honest qualifications

1. **Only the cadence axis moved.** Speed slope +0.0012 is 0.1× noise — statistically unchanged.
   The wider actor bought cadence differentiation, not speed differentiation.
2. **Max speed error regressed** 0.0442 → 0.0505 even though the mean improved. The worst cell got
   worse; the average got better.
3. **Cadence correlation is flat** (−0.7026 → −0.7017). The response *magnitude* grew; the scatter
   did not tighten. The policy is not tracking cadence more faithfully, it is responding less
   weakly in the wrong direction.
4. **The sign is still negative** (−1.5565). Inversion is reduced, not removed. At +0.0774 per
   294,912 steps the sign would flip in ~5.9 M further steps — but the arc has repeatedly shown
   these rates do not hold (row 135 reversed), so that number is indicative only.

## 4. The function-preserving widening

Required by the ticket and proven before training. Pure zero-padding gives parity but **dead
units** (zero in *and* out ⇒ zero gradient forever); Net2Net replication gives live gradients but
only approximate parity and symmetric twins. Construction used: **new units get random incoming
and zero outgoing weights** — exact parity because the outgoing weight is 0, live gradient because
the activation is not.

```
policy_net.0 (54→512)   rows[0:256]=old        rows[256:512]=orthogonal, bias 0
policy_net.2 (512→512)  [0:256,0:256]=old      [0:256,256:512]=ZERO   ← old units unaffected
                        [256:512,:]=orthogonal  bias[256:512]=0
action_net   (12×512)   [:,0:256]=old          [:,256:512]=ZERO       ← exact parity
```

**Step-zero action parity through the deployed g_v1 over 512 observations: max |diff| =
4.768e-07**, within float32 eps. Not bit-identical only because the widened matmul sums 512 terms
where the extra 256 are exactly zero — float accumulation order, not a functional difference.

Every new block is gradient-reachable: `action_net[:,256:]` and `policy_net.2[0:256,256:]`
immediately, the remainder as soon as those move.
