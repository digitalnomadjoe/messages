## 1. Final acquisition domain — a rule, not a shrunken box

12U-C11S15FAM found the DFL boundary. This unit found the **mechanism** behind it, which turns a scatter plot into three separable inequalities. Everything is judged against a **margin rule declared up front and never relaxed for a cell I wanted**: `SS P10 ≥ −16.5 mm` (1.0 mm inside the −17.5 bar) and `med-integ ≤ 2.43 mm·s` (10 % inside the 2.7 bar). **The DFL thresholds themselves are untouched — this is a stricter band drawn inside them.**

```
v  ∈ [0.10, 0.24] m/s        c ≤ 1.00 Hz        stride = v/c ≤ 0.28 m        |κ| ≤ κ_max(v)
```

★★★ **The two boundaries are different constraints, and separating them is what makes the domain describable.**

**(a) `c ≤ 1.00` is speed-independent.** `c = 1.05` is rejected at *every* speed — including `v = 0.10`, where the stride is only 0.095 m. Nothing about step length can explain that, so it is a short-cycle bound. Margins at `v = 0.153`: `c` 0.95 → +2.6 mm, 1.00 → +1.8, **1.05 → +0.1**, 1.10 → 0.0 (exactly on the bar), 1.15 → −0.4. The ticket asked for margin rather than a zero-margin edge; **1.00 is the last cadence with real margin and that is the bound.**

**(b) The low-cadence boundary is a STRIDE bound — proven, not assumed.** Hold stride fixed and slide `(v, c)` along it:

## 3. Cadence integrity gate — fail-closed, on actual geometry

`cadence_integrity_gate()` (new, in the trainer, called by the sparse resolver on every member). Authoritative definitions, now enforced rather than assumed: **cadence = same-foot gait-cycle frequency; step rate = 2 × cadence; the phase clock is a separate quantity.** Neither the filename nor `gait_cycle_hz` is trusted — 12U-C11S15SR found a whole family whose cadence axis existed only as metadata. Four checks, each aborting:

1. measured same-foot cadence vs declared, ≤ 2.5 %;
2. npz `gait_cycle_hz` vs the manifest (metadata self-consistency, *after* the measurement);
3. **step rate / cadence = 2.000** ± 5 % — catches a schedule where the feet are not alternating one step per half cycle;
4. the loop must span a **whole number of gait cycles**, or the cyclic clock drifts against the gait at every wrap.

All 18 pass: cadence error ≤ 0.13 %, step-rate ratio 2.009–2.011, exactly 5 whole cycles in every loop.

## 4. Canonical realized-path metric, and the banked actor's baseline

**`rl/bridge/path_speed_v1.py` is now the single pinned estimator.** It exists because three estimators in prior use each gave measurably wrong answers: raw pelvis arc length inflates speed by the sway (+24 % on this base); median-of-differences cadence quantizes to whole frames (read 0.847 for a commanded 0.850); endpoint-differenced curvature read **|κ| up to 1.02 rad/m on a straight reference**. The method: segment on done/teleport → cadence from same-foot touchdowns by total span → cycle-synchronous box filter exactly one measured gait cycle long → path speed from the smoothed increments → **curvature as the least-squares slope of unwrapped heading against cumulative arc**, with the fit residual returned as the estimator's own noise floor → stride = speed / cadence. It is fail-closed: a segment that cannot support the method is reported invalid with a reason and contributes to nothing.

**Banked actor `g_v1`, 32 worlds × 900 steps per command, 32/32 measurable:**

| command | κ commanded | **path speed** | **cadence** | **curvature** | **stride** |
|---|---|---|---|---|---|
| straight | 0.0 | 0.1621 | 1.0949 | +0.0004 | 0.1479 |
| medium left | +1.0 | 0.1489 | 1.5134 | +0.9219 | 0.0982 |
| medium right | −1.0 | 0.1486 | 1.5089 | −0.9341 | 0.0984 |
| tight left | +2.0 | 0.1444 | 1.4784 | +1.6998 | 0.0977 |
| tight right | −2.0 | 0.1443 | 1.4784 | −1.7238 | 0.0974 |

★★★★ **THE HEADLINE, AND IT IS THE REASON THIS BASELINE MATTERS: turning drags cadence from 1.095 Hz to 1.51 Hz — +38 % — with nothing commanding it, while stride collapses 0.148 → 0.098 m.** This is exactly the failure mode 12U-C11S15SR listed as held-out criterion (7) and the SC preflight estimated at +39 %; it is now **confirmed on the banked actor with the pinned estimator**. ## 5. Advantage normalisation — replaced, and demonstrated on real data

The old `--adv-norm-per-regime` was four hardcoded masks on obs45 sign plus a binary obs53 hold test, `_regime_telem` fixed at `range(4)`, **no cadence dimension at all**, and a **silent** fallback to global statistics whenever a mask held < 64 rows. `--adv-norm-command-regime` replaces it. Three things changed and each was a defect:

- **strata are the declared command regimes, carried per world.** Stratum identity comes from the manifest — `(role, κ-sign, cadence)` — and is assigned to each world at wiring time, never re-inferred from obs45. That matters: obs45 = v·κ reads ~0 wherever the reference holds, which would silently reclassify a curved world as straight.
- **statistics are computed once per iteration over the full batch**, then applied to minibatch rows, so a minibatch can never be too small to normalise. Occupancy is guaranteed by round-robin world assignment.
- **occupancy is asserted and printed; there is no fallback path at all.**

Measured, on a real 589,824-sample rollout (1152 worlds × 512 steps, **no optimizer step taken**) — 9 strata, all occupied:

```
acq_kap0_c0.85    n=98304   acq_kap0_c1.00    n=98304   acq_kap0_c0.70    n=65536
acq_kapP_c0.85    n=98304   acq_kapM_c0.85    n=98304
acq_kapP_c1.00    n=32768   acq_kapM_c1.00    n=32768
anchor_kapP_c1.00 n=32768   anchor_kapM_c1.00 n=32768
```

The anchors get **their own strata**, so a retention anchor's advantages are never normalised jointly with an acquisition member's. **The no-fallback behaviour is demonstrated, not asserted**: at `nworld = 1080` the four single-member strata hold 3840 samples and the run aborts —

```
BLOCKER adv-norm-command-regime: under-occupied strata acq_kapP_c1.00=3840 < 4096, ... 
  -- refusing to fall back to global statistics
```

Sizing rule that follows: `(nworld / 18) × n_steps ≥ 4096`, so `nworld ≥ 1152` at `n_steps = 64`.

## 6. Post-reset command freshness — fixed and regression-tested

`--cmd-obs-fresh` rebuilds obs45 from the member's yaw profile at the **current** phase inside `_augment_obs`. Without it, obs45 came from the GPU obs buffer computed *before* the respawn injection, so a world that just reset acted once on its **pre-respawn** command (12U-C11S15FAM blocker B4).

Regression, 4,130 post-reset rows in the dry proof:

| channel | max abs error | verdict |
|---|---|---|
| **obs52** | 5.4e-09 | fresh — float32 rounding |
| **obs53** | 1.2e-08 | fresh — float32 rounding |
| **obs45** | 0.0140 | **post-reset fresh to within one reference frame** |

⚠ **The obs45 residual is characterised, not waved through.** The worst row is world 278 at phase 6078, member start 6075 — three frames *into* the post-reset member, so the value is unambiguously post-reset and not the pre-respawn command. Its observed obs45 is **exactly `profile[phase−1]`** (0.024320337921380997, matching the −1 entry of the profile window to every digit). It is a **uniform one-frame observation lag** shared by every phase-derived channel — the sin/cos clock and the tracking errors have it too — not a command-staleness bug. Its magnitude is bounded by the profile's own per-frame delta: **≤ 0.0157 anywhere and ≤ 0.0122 inside the loop**, across all 18 members. Before the fix the error was a whole episode's worth of command; after it, one frame. Removing the last frame means changing when the phase counter advances relative to the observation build, which touches every observation channel — **out of scope here, recorded as debt.**

`--cmd-retime-range 0` is **pinned by the resolver**, which refuses to run otherwise: with retime > 0, `vx_cmd` and `cadence_cmd` are resampled *after* the observation is built, so obs52/obs53 would be stale exactly the way obs45 was.
