## 1. What the conflict actually was

⚠ **My Q10A attribution was wrong and the ticket's was right.** I had blamed the staging artifact (a 1944-frame 3-member concat). That artifact was real and did need fixing, but it was not the cause. The cause is a genuine spectator conflict, and it was already documented — in the runtime manifest's own `cmd_note`, written by 12U-C11S15O6:

> *"in cmdphase54 mode the spectator returns from the obs wrap BEFORE `_p52_update()`, so the profile-ref supplies only the phase clock and NEVER writes the yaw command — obs45 stayed at first_frame_cmd."*

`_obs_for_policy()` returns inside the `obs_cmdphase54` branch (`isaac_spectator.py:501`) before reaching `if obs_phase52: self._p52_update()` (`:503`), and `_p52_update()` is the only place that writes `e._cmd` from the profile. O6 worked around it by pinning `command.first_frame_cmd` to a constant −0.306 — **which is exactly the constant I measured three times in Q10A.** Second defect in the same branch: `self._p52_phase = int(min(self._cp54_acc, self._p52_n - 1))` **saturates** at `n−1`, so a review profile can only ever run once and then pins forever.

## 2. The fix — spectator only, opt-in, three edits

`rl/scripts/isaac_spectator.py` `aac6347001f1ef3e` → **`65249316b6b5fea8`** (prior file preserved as `spectator_PRIOR.py`). `isaac_spectator.py` is **not** a bound-construction member, so D-11 is untouched.

1. **New flag `--live-cmd-profile`** (opt-in; absent ⇒ every pre-existing invocation is bit-unchanged).
2. **In the `obs_cmdphase54` branch, with the flag set:** wrap the phase (`int(acc) % n`) instead of saturating, read the profile at the live phase, write it to `e.yaw_cmd_fixed` / `e._cmd`, **and write it into `base50[45]`** — the vector the policy actually consumes, since `ob` was already built by the env before this point.
3. **Telemetry** now prints the live `cmd`, the normalized `F`, and `obs45`, so the ramp is visible during review.

★ **A bug I introduced and caught before it ran.** My first telemetry version called `streamer._obs_for_policy()` to read obs45 — but that function *increments* `_cp54_acc`, so printing would have advanced the phase clock a second time every 25 steps and silently corrupted the ramp. Replaced with a cached `_live_obs45` written at the same point as the command.

**Regression check:** the established Q8C-style invocation *without* the flag was re-run — same startup banners, and the telemetry line is byte-identical to before (no `cmd=` suffix). Nothing existing changes.
