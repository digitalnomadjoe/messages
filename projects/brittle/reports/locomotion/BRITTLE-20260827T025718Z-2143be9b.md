## 2 · The repair

One helper, called by both paths, so the two lists cannot diverge again — which is exactly how this defect arose:

```python
def _respawn_clear(self, m, foot_xy=None):
    if not np.any(m): return
    self.dwell[m] = 0.0
    self._aw_t[m] = -1.0; self._aw_inc[m] = 0.0
    self.ss_dur[m] = 0.0; self.cur_ssfoot[m] = -1.0; self.was_ss[m] = False
    self.cad_since[m] = 0.0; self.cad_has[m] = False
    self.cad_rho[m] = 0.0; self.cad_prev[m] = True
    self.strdc_g[m] = 0.0; self.strdc_n[m] = 0; self.strdc_since[m] = 0.0
    if getattr(self, "_ast_valid", None) is not None:
        self._ast_valid[m] = False; self._ast_slide[m] = 0.0
    if foot_xy is not None:
        self.prev_foot_xy[m] = foot_xy[m]
```

Every clear is a constant, so calling it twice on a row is **idempotent** — that is what lets the termination path keep its existing `_ast_*` clears at `:3320-3321` while the helper also covers them, with no behaviour change.

**Termination path** (`:3384`): `prev_foot_xy` stays an unconditional all-worlds refresh — it is the normal per-step update, not a respawn clear, and scoping it to `dm` would have broken `foot_trans` for every walking world. The 13 respawn clears become `self._respawn_clear(dm)`.

**Truncate path** (after `:3597`): the same helper, after the teleport, with post-teleport feet —

```python
_fin_done = np.zeros_like(fin); _fin_done[fidx] = True
_ft_post = self.sim.get_foot_xpos()[:, :, :2].astype(np.float64)
self._respawn_clear(_fin_done, foot_xy=_ft_post)
```

`batch_sim_tip.set_state` runs `mjw.kinematics` + `mjw.com_pos` (`:1541-1542`), so `get_foot_xpos()` there is genuinely post-teleport. `prev_foot_xy` therefore describes the new physical state before the next reward step, and a teleport displacement can no longer be read as a foot velocity by `foot_trans` (`:2988`, amplified ×20 at `:2989` and uncapped since `hold_tax_cap` defaults 0.0).
