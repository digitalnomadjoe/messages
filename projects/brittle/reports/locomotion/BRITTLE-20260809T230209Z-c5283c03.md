## 3. The mechanism — mean error improved while command response got worse

This is the subtle part, and it is why the slope gate exists.

| cell | cadence G | cadence H | \|cad err\| G → H | speed G → H | \|v err\| G → H |
|---|---|---|---|---|---|
| c=0.70 | 1.8882 | 1.8317 | 1.188 → **1.132** | 0.1422 → 0.1437 | 0.0108 → **0.0093** |
| c=0.85 | 1.6477 | 1.5516 | 0.798 → **0.702** | 0.1513 → 0.1561 | 0.0017 → 0.0031 |
| c=1.00 | 1.2652 | 1.1398 | 0.265 → **0.140** | 0.1694 → 0.1778 | 0.0164 → **0.0248** |

**Every cadence error improved. The slope still got worse.** Both are true because all three
realized cadences fell, but they fell *more at high `c_cmd` than at low* (−0.1254 at c=1.00 vs
−0.0565 at c=0.70). Since realized cadence sits above command everywhere, a uniform drop shrinks
every individual error while **widening the spread** — 0.6230 → **0.6919 (+11.1 %)** — which is
exactly a steeper inversion.

**Mean tracking error and command responsiveness moved in opposite directions.** Any future
report that judges this axis on mean \|cadence err\| alone will read this run as an improvement.
It is not one.

## 5. Which hypothesis survived

Three outcomes were pre-declared in the mining producer before the run finished:

| | prediction | verdict |
|---|---|---|
| **H1 ratio-driven** | reproduces probe D — slope improves, band breaks | **DISCONFIRMED** |
| **H2 rebalance works** | speed back in band, slope regresses modestly | **DISCONFIRMED** |
| **H3 scale slack** | both regress; freed reward goes to survival | **CONFIRMED** |

**H1 is the informative rejection.** Probe D moved the cadence : forward ratio 1.625 → 1.30 *by
raising fwd* and the slope **improved** (+0.1268). Probe H moved it to 1.25 *by lowering cadence*
and the slope **degraded** (−0.2297). Same ratio, opposite outcomes ⇒ **the operating point is not
set by the ratio.** It is set by the **absolute cadence income**. That kills the framing that
motivated the ticket, and it also retires my own row-129 suggestion that the weight *ratio* was
the thing to move — it was the wrong variable, and this run is what shows it.

**H3's signature is unmistakable in the training trace:**

| step | ep_len | young-death % | mean_track | EV |
|---|---|---|---|---|
| 147,456 | 45.5 | 100.0 | 0.431 | 0.686 |
| 442,368 | 131.5 | 100.0 | **8.161** | 0.815 |

Survival improved enormously — 4× the episode length of probe G, young-death nearly eliminated,
EV up from 0.492 to 0.849. **That is the slack going somewhere.** It went to staying upright, and
`mean_track` peaked at 442K and then *declined* while survival kept climbing — the two trading
against each other.

⚠ **`mean_ep_ret` is NOT comparable across this run.** Return is computed under a different reward
book (cadence 15.0 vs 19.5), so G→H return deltas are meaningless and are excluded throughout.
Only weight-independent quantities are compared: `ep_len`, realized speed, realized cadence,
stride, slope, survival.

## 6. ⚠ The λ = 0.99 repair and the cadence weight are not independent

| probe | cadence_w | λ | slope |
|---|---|---|---|
| C | 19.5 | 0.95 | −2.3161 |
| **G** | **19.5** | **0.99** | **−2.0766** (+0.2395) |
| **H** | **15.0** | **0.99** | **−2.3063** (−0.2297) |

**Probe H sits within 0.0098 of probe C — inside the 0.0394 noise range.** With λ = 0.99 still
in place, dropping the weight 23 % returned the slope to its pre-repair value. The long credit
horizon only pays if there is enough cadence income for it to attribute; the two **multiply**
rather than add.

Your ticket's premise — *"λ = 0.99 made cadence credit substantially more effective"* — is
correct, and this run is the evidence for it. It just implies the opposite intervention.

## 7. ⚠ Two defects found, neither repaired

**1. The card's post-run assertion is stale, and it aborted the run's own gate.**
`launch_ident_probe.sh` verifies the resolved config against a **hardcoded literal**:

```
if w is None or abs(float(w) - 19.5) > 1e-9:
    raise SystemExit(f"BLOCKER: resolved cadence_track_w is {w!r}, expected 19.5")
```

Probe H resolves 15.0, so this fired under `set -e` **after training completed**, exiting 1.
Everything downstream of it was skipped — including the `episode start` check and **the bound
slope gate**, which is why the run produced no `cadence_gate.json`. The Guard run record
`R-05e022f6d1d6` is therefore **FAILED exit 1** while the training itself completed 6/6 iterations
and wrote all 3 checkpoints.

**The measurements in this report are unaffected**: I ran the same bound producer
(`rl/bridge/cadence_slope_gate.py`, pinned `1125b30033225ed5`, verified before use) directly on
each checkpoint. But the run's own receipt is missing, and **this will block every future probe
that moves this weight**. Note the *pre-run* argv assertion is written correctly — it compares
against `$CADENCE_W` — so only the post-run check hardcodes the constant. I have **not** repaired
it: the launcher is a bound Guard member and that is a canonical mutation this ticket does not
authorize.

**2. My mining producer treated a FAIL verdict as a crash.** The slope gate exits **3 for a
legitimate FAIL** and 0 for PASS; my first pass used `check=True` and threw
`CalledProcessError` on the final checkpoint — discarding the very result that matters. Fixed to
accept {0, 3} and fail loudly on anything else. First pass discarded, not reported.

## 8. Recommendation

**Restore `cadence_track_w = 19.5` and branch from probe G `e6d656cee2863727`.** Probe H is a
clean negative and its checkpoints have no residual value.

**The usable direction is up, not down.** The row-116 licence is an upper bound `w ≤ 20.104`
(subordination to `track_feet`); 19.5 sits at 97.0 % of one `track_feet` and 20.0 is the 0.5-grid
value still under the ceiling. That is a **+2.6 %** move — small, and §6 says the slope is
*steeply* sensitive to this weight (a −23 % move cost 0.2297 of slope), so a +2.6 % move is worth
one bounded probe. I am not projecting that it clears the band.

**What this run rules out for the speed band:** the band cannot be recovered by trading cadence
income away. Probe D (raise fwd) broke it; probe H (lower cadence) breached it in the *opposite*
direction. Both levers on the existing two terms are now spent. The remaining candidates are
structural, not weight-tuning — the row-125/126 finding that differentiation has no home in the
actor's representation, and the standing lesson that it must live in recurrent/phase **state**.
That is an architecture question and it is **yours to decide**, not a knob I should turn.

**Fix the card's post-run assertion first** — otherwise the next probe that moves this weight
fails the same way, after paying for the training.
