## 3 · Root cause and the minimal repair

Constructor, `:350-352`:

```python
self._ref_qvel = np.zeros((self.n, 18), dtype=np.float64)
self._ref_qvel[1:, 0:3]  = np.diff(self.tpos, axis=0) / 0.02
self._ref_qvel[1:, 6:18] = np.diff(self.jq,   axis=0) / 0.02
```

`tpos` is the **concatenation of 23 members' absolute world positions**. A first difference across it is a genuine velocity *inside* a member and a **splice artifact at every boundary**. Measured on this family (16,718 frames):

| | |
|---|---|
| frames with `\|v_lin\| > 10 m/s` | **22** — exactly the 22 internal boundaries of 23 members |
| their values | 41.08 – 124.91 m/s |
| every spike an isolated single frame | **True** |
| median / p99 / max excluding spikes | 0.1392 / 0.3559 / **3.7009** |
| frame 16440 | **93.6832 m/s → 1.8737 m in one step** (observed foot move 1.725/1.965 m) |

`_bent_state` (`:947`) reads this table for **every** respawn injection — err-ET, `walk_rsi`, `arc_rsi` and `--init-zone` alike.

**The repair.** A member's first frame has no in-member predecessor, so its velocity is not defined by a difference. Those rows are zeroed — the same convention the constructor already applies to row 0, which is allocated zero and never filled. Placed at the manifold wiring site, the earliest point where member offsets exist:

```python
if getattr(env, "_ref_qvel", None) is not None:
    _starts = np.unique(np.asarray(_get("off", np.int64), np.int64))
    _starts = _starts[(_starts > 0) & (_starts < env._ref_qvel.shape[0])]
    if _starts.size:
        env._ref_qvel[_starts, 0:3]  = 0.0
        env._ref_qvel[_starts, 6:18] = 0.0
```

Runtime receipt, identical in all four runs: `ref_qvel splice repair: zeroed 22 member-start rows (max |v_lin| there was 124.91 m/s; family max elsewhere 3.701 m/s)`.

**Deliberately not done**, per §3: I did **not** cap `r_lift` or `foot_trans`. The evidence shows the physical term is not unbounded after correct initialization — with the splice removed, `max |parent|` is 62.1, inside the normal population. Nothing needed a clamp; the input was wrong.

**On §3's "reuse the RC2 shared reset semantics":** RC2's `_respawn_clear` owns *history* variables. This is not a history variable — it is a precomputed reference table, and folding a table correction into a per-world reset list would have been the wrong shape. The two repairs are orthogonal and I kept them so.
