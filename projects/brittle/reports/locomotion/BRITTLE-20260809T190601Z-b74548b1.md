## ⚠ The cosine was the wrong instrument, and I recommended it

`cos(cadence, speed)` rose again — 0.9163 → **0.9251** — in the run where the behaviour finally
*decoupled*. Coherence rose too (0.470 → 0.492).

In rows 121 and 122 I recommended gating the next budget on the cosine falling. **That
recommendation was wrong.** The cosine is a feed-forward action-space property of the actor; this
run changed *what the credit path could attribute*, not how obs53 is encoded, so the behaviour
decoupled while the encoding did not. The instrument that tracked the real mechanism throughout is
the **speed/stride decomposition** — it read 49.8 % → 62.0 % speed on the probes that were
coupling and **−8.2 %** here. Gate on that, not the cosine.

## ⚠ Two things to carry into the long run

**1. Explained variance dropped: 0.813 → 0.672 → 0.492.** Expected — λ = 0.99 makes the value
target longer-horizon and higher-variance, so the critic has a harder job. It is not yet harmful
(survival and return both held: `ep_len` 74.7, `ep_ret` 3.91), but over a long budget a critic
that cannot keep up will erode the advantage estimates that this whole repair depends on. Watch
EV, and treat a sustained fall below ~0.4 as a stop condition.

**2. No run receipt records `gae_lambda`.** `resolved_config.json` and `settings_summary.json`
both omit it, so the one knob this probe turned is not captured in any artifact. I bound it the
only way available: the Guard run receipt hash-binds the executed script to
**`2fb17d694a89f30d`**, and that exact file carries `GAE_LAMBDA="0.99"` and
`--gae-lambda "$GAE_LAMBDA"` in `TRAINER_ARGS`, with the trainer's GAE loop reading
`args.gae_lambda` directly (`train_tip_reftrack.py:5531`). That is a sound binding, but it is
indirect — the same class of gap as `njmax` being launch-pinned but unobservable. Worth closing
before a long run, so the receipt proves λ rather than the launcher hash implying it.
