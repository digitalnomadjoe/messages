# WALK-DR06H3A · Cadence Timing Coherence Preflight

ZERO PPO. Owner-issued (Joe, 2026-08-26).

## Context
WALK-DR06H3 preflight found a load-bearing hidden timing mismatch before PPO:
- cadence_track target at the ratchet member = 1.0 Hz
- phase/reference playback = schedule-compressed to 1.0 Hz
- sim.set_rp_step_period_w remains derived from the member cadence: ~0.7177 Hz / 1.3933 s
- F8 is off, so that sim-side period is never refreshed
The proposed cadence-led run currently contains two different gait periods.

## Objective
Make cadence/timing semantics internally coherent before authorizing WALK-DR06H3 training.
Do not change reward architecture, stride imitation, plant, observations, action interface,
or gait geometry.

## 1. Trace every cadence/period consumer
From the LIVE trainer/card enumerate every runtime consumer of: c_member, cadence_cmd,
scheduled cadence, realized cadence, rp_step_period_w, phase clock / reference playback rate,
touchdown / gait-period timing. Print the actual value each consumer receives for the ratchet
member. Identify any remaining source still using the banked 0.7177 Hz member cadence.

## 2. Establish one runtime timing authority
All runtime timing mechanisms representing the active gait period must bind to the same
scheduled cadence semantics. At the ratchet member: cadence_cmd 1.0 Hz, period 1.0 s.
Minimum scoped plumbing change for sim.set_rp_step_period_w to follow the active cadence.
Do not change the legacy schedule. Default/unrelated lanes byte-identical.

## 3. Non-perturbation proof
Prove: H3 ratchet phase/reference period = 1.0 s; H3 sim-side gait period = 1.0 s; no stale
1.3933 s consumer active; lower-speed members receive their own scheduled cadence coherently;
F8 behavior unchanged; default behavior outside the opt-in path byte-identical.
Serialize effective cadence and period values into resolved_config.

## 4. Clarify the stride contract
Do NOT claim stride is observational-only. State: CADENCE-LED WITH FROZEN REFERENCE GEOMETRY.
track_feet, track_jnt, track_rest, fwd_dominant remain active and unmodified.
Purpose: can improved realization of the scheduled cadence move the existing gait to
>=0.29 m/s without adding explicit stride_track or stride_corridor objectives?

## 5. Re-dry-prove H3
stride_track_w=0, stride_corridor_w=0, cadence_track at precedent weight, one coherent
scheduled cadence/gait period, card and resolved_config agree, reward fingerprint/dependency
receipts valid, no optimizer steps. Then STOP for Joe, request fresh authorization with exact
hashes/card/budget.

## Required report
rgl/reports/ — timing-consumer map, before -> after cadence/period values, exact scoped change,
non-perturbation proof, resolved_config receipt, final H3 dry-proof status.
