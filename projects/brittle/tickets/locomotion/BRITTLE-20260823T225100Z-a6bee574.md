## Objective
WALK-DR01 — Isaac Crown DR Basin Acquisition (TEAM: GREEN, owner-direct from Joe in chat, 2026-08-23).

Expand the existing frozen Crown walking policy's physical robustness in Isaac
WITHOUT changing its walking function. We are NOT redesigning locomotion.

Frozen product behavior: SPEED + CURVATURE, cadence internal, same
obs/action/control law, same Crown gait, same reward, same command manifold.

Primary question: Can PPO expand the Crown's physical robustness basin while
preserving nominal gait quality and command behavior?

## Steps

### 1. Zero-training DR sensitivity map
Start from the frozen Crown / qualified Isaac implementation. Before PPO,
measure Crown performance under progressively increasing perturbations. Use
ONLY existing/defensible simulation parameters. Do not invent hardware
uncertainty ranges. Evaluate DR families separately first:
- A. CONTACT: floor friction; contact/material parameters already supported by the Isaac model
- B. ACTUATION / CONTROL: actuator strength / torque scale; existing control gain/model variation where already supported
- C. PLANT: link mass; inertia / CoM variation where supported
- D. OBSERVATION: existing realistic sensor noise / latency machinery if already implemented

Do not combine families until their individual sensitivity is measured.
No terrain randomization in this unit.

### 2. Find the first failing shell
For each DR family identify: certified/healthy region, transition region,
first clearly failing region. Track at minimum: survival, commanded speed
realization, curvature realization, stride, slip, body tilt, DS/contact
quality, torque distribution, foot-foot physical collision, command
symmetry/monotonicity. Preserve the existing Crown success semantics. Do not
create new relaxed gates to make DR pass.

### 3. Choose ONE training target
Select the highest-value FIRST failing shell. Prefer the perturbation family
that: causes the earliest meaningful degradation, is physically relevant, does
not require an owner hardware assumption, can be trained without changing
architecture. Report the choice before PPO. If multiple equally plausible
targets require an owner decision: STOP for Joe.

### 4. Nominal-anchored PPO
Train from the frozen Crown. Use the existing qualified PPO stack.
Sampling: 80–90% selected DR shell, 10–20% exact nominal (mandatory).
Purpose: robustification must not destroy the gait we already own.
No: reward changes, obs/action changes, cadence command, reference changes,
RGL/DFL changes, teacher changes, specialist switching.

### 5. Monotonicity
Deterministically evaluate checkpoints throughout training. Want: nominal
preserved + DR robustness improves monotonically. Do NOT cherry-pick a
transient checkpoint. Track separately NOMINAL SCORE and DR SCORE. A useful
checkpoint must improve DR while remaining inside the frozen nominal
acceptance envelope. If PPO improves DR by degrading nominal Crown behavior:
FAIL / STOP.

### 6. Command manifold
Do not certify robustness only at one straight-line command. At minimum
preserve representative: low/nominal/higher SPEED, straight, +CURVATURE,
-CURVATURE. Ensure DR does not create one-sided behavior, loss of curvature
gain, non-monotonic speed response, or command elements fighting each other.
Keep the test compact; use existing certified command points where possible.

### 7. Physical validity
Permanent invariant: any actual left-foot ↔ right-foot physical collision =
FAIL. Track torque against current hardware model: cap 12.5 Nm, prefer
sub-10 Nm behavior. Do not hide robustness gains behind increased saturation.

## Acceptance criteria
PASS if: first DR shell materially expands; nominal Crown remains qualified;
command manifold remains healthy; no physical foot collision; torque remains
acceptable; improvement persists through continued PPO. Then report
"FIRST WALKING DR BASIN EXPANDED" and STOP for Joe. Do NOT automatically
broaden to every DR family. The next unit should widen ONE axis or combine
already-qualified families incrementally.

## Prohibitions
No Crown/latest/main promotion. No canonical mutation. No obs/action/interface
change. No terrain training. No TIP work. No reward changes. No new relaxed
gates.

## Execution requirements
Use CACHE_WORKER_ENV=True. PPO headless. Run the independent visible Isaac
inspector/spectator throughout training; it must not affect training and must
close when the report is complete. Final report under rgl/reports/.
STOP for Joe.
